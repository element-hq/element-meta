# AI policy

This policy applies to contributions to all Element projects: the repositories of
[element-hq](https://github.com/element-hq), and the [matrix-org](https://github.com/matrix-org)
repositories where Element is the core contributor.

Contributions are judged on their content, not on how they were produced. AI-assisted contributions
are accepted; unreviewed AI output is not. AI is a tool, not a substitute for your own engineering
judgement. The rules below apply regardless of how the code was written. We expect the following
from you, and close PRs that don't meet it:

1. **Start with an issue:** Open an issue and wait for a maintainer to validate it **before** you
   write code. This is how we agree on the problem, the scope, and the approach from a product and
   engineering perspective.
   - Features and behaviour changes: always need a validated issue. For the Element apps, see
     [Feature requests](feature-requests.md).
   - Complex bug fixes: need an issue describing the problem and the proposed fix, validated by a
     maintainer.
   - Simple bug fixes: need an issue describing the problem. You can open the PR right away.
   - Typos and small doc corrections: can go straight to a PR.
2. **Transparency:** If your PR was made with the help of AI, you **must convey** that this is the
   case using the PR template.
3. **Accountability:** You are fully responsible for the quality of the PR. **You must thoroughly
   review the code yourself** to ensure that you understand every change and that it is of high
   quality. It is unfair to leave the burden of this with the reviewer. If a PR doesn't show
   **effort** on your part (code does not compile, code does not work as expected, code with no
   test, no screen recordings or screenshots, etc.), it will be closed.
4. **Communication is yours:** Issues, PR descriptions, commit messages and review replies must
   reflect your own understanding. **Don't paste LLM essays.** Keep them short and write them
   yourself. Commit messages may be AI-drafted, but you **must review** them and rewrite them if
   needed. Machine translation and grammar/spelling tools are fine.

**In return**, every PR is reviewed and approved by a **human maintainer**.
